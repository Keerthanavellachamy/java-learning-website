What is Method Overriding?

Method overriding happens when a child class provides its own version of a method that already exists in the parent class.

The method in the child class must have the same method name, parameters, and compatible return type as the parent method.

Parent Method
→
Child Method
Method overriding is mainly used to achieve runtime polymorphism in Java.

Basic Example

Suppose an Animal has a method called sound(). A Dog can override that method and provide its own implementation.

Animal.java 
class Animal {

    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {

    void sound() {
        System.out.println("Dog barks");
    }
}

@Override Annotation

Java provides the @Override annotation to clearly indicate that a method is being overridden.

Using @Override 
class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
The compiler checks whether the child method correctly overrides a method from the parent class.

Complete Method Overriding Program

Main.java 
class Animal {

    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

public class Main {

    public static void main(String[] args) {

        Dog dog = new Dog();

        dog.sound();
    }
}
Dog barks

Why Do We Override Methods?

  • To change inherited behavior.
  • To provide a specialized implementation.
  • To support runtime polymorphism.
  • To make parent classes more reusable.
  • To allow different child classes to behave differently.

Rules of Method Overriding

  • The method must exist in the parent class.
  • The child method must have the same name.
  • The parameter list must be the same.
  • The return type must be the same or compatible.
  • The child method cannot reduce access visibility.
  • Static methods are not overridden.
  • Private methods are not overridden.
  • Final methods cannot be overridden.

Access Modifiers and Overriding

A child class can increase the visibility of an overridden method, but it cannot reduce the visibility.

AccessExample.java 
class Parent {

    protected void show() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    @Override
    public void show() {
        System.out.println("Child");
    }
}
protected → public is allowed because visibility becomes wider.

Overriding with super

Sometimes the child class wants to use the parent version and then add its own behavior.

SuperExample.java 
class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {

        super.sound();

        System.out.println("Dog barks");
    }
}
Animal sound Dog barks

Overriding vs Overloading

Overriding Overloading
Occurs between parent and child classes. Usually occurs within the same class.
Same method name and parameters. Same method name but different parameters.
Supports runtime polymorphism. Supports compile-time polymorphism.
Inheritance is required. Inheritance is not required.

Real-World Example

Consider a payment application. A general Payment class can have a pay() method. Different payment types can override this method.

PaymentExample.java 
class Payment {

    void pay() {
        System.out.println("Making payment");
    }
}

class UPIPayment extends Payment {

    @Override
    void pay() {
        System.out.println("Payment using UPI");
    }
}

class CardPayment extends Payment {

    @Override
    void pay() {
        System.out.println("Payment using Card");
    }
}
Each child class provides its own implementation of pay(). This makes the application easier to extend with new payment methods.

Method overriding allows a child class to change the implementation of a method inherited from its parent. The @Override annotation helps the compiler verify that the method is correctly overridden.
